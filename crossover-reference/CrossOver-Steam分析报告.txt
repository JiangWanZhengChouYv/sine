# CrossOver Steam 支持分析报告

## CrossOver 版本
- Product: CrossOver 26.2.0 (Build: cxoffice-26.2.0rc2)
- 安装路径: ~/Applications/CrossOver.app

## 关键发现

### 1. SuppressAltLoader 注册表项
在 crossover.inf 中发现：
```
HKCU,"Software\CrossOver\SuppressAltLoader","steam",0x10001,0
HKCU,"Software\CrossOver\SuppressAltLoader","steamsysinfo",0x10001,0
```

含义：CrossOver 针对 Steam 禁用"替代加载器"(Alternate Loader)。
替代加载器是 CrossOver 用于拦截进程创建行为的组件。禁用后，
Steam 以更接近原生 Windows 的方式运行，避免 CEF 多进程冲突。

### 2. NtCreateUserProcess 系统调用补丁
在 cxcompatdb.so 中发现字符串：
```
couldn't find NtCreateUserProcess in syscall table
```

含义：CrossOver 对 Windows 的 NtCreateUserProcess 系统调用做了特殊处理。
CEF 使用多进程模型（Browser+Renderer+GPU进程），需要频繁创建子进程。
纯上游 Wine 对 NtCreateUserProcess 的实现不完整，导致 CEF 子进程异常。

### 3. apply_in_process_hacks
在 cxcompatdb.so 中发现：
```
apply_in_process_hacks
```

含义：CrossOver 有"进程内 hack"机制，可能针对特定进程（如 Steam CEF）
注入修复代码或修改运行时行为。

### 4. 兼容性数据库 (cxcompatdb.so)
纯上游 Wine 没有此组件。它包含：
- 程序识别规则（通过进程名、窗口类等）
- 针对性修复策略
- Steam 游戏 ID 匹配

### 5. Apple GPTK 支持
CrossOver 包含 apple_gptk 目录：
- lib64/apple_gptk/wine/x86_64-unix/d3d11.so
- lib64/apple_gptk/wine/x86_64-unix/d3d12.so
- lib64/apple_gptk/wine/x86_64-unix/dxgi.so

这是 Apple Game Porting Toolkit 的 D3D→Metal 翻译层，
CrossOver 专有，不开源。

### 6. DXVK 支持
CrossOver 包含 lib/dxvk 目录：
- d3d9.dll, d3d10.dll, d3d10core.dll, d3d11.dll
- i386-windows 和 x86_64-windows 两个架构

## 结论

CrossOver 能运行 Steam 的核心原因：

1. **Wine 二进制层面的 CEF 补丁**
   - NtCreateUserProcess 系统调用修复
   - 进程内 hack 机制
   - 这些补丁不开源，无法复制

2. **兼容性数据库 (cxcompatdb.so)**
   - 程序识别和针对性修复
   - 纯上游 Wine 没有此组件

3. **SuppressAltLoader 机制**
   - 针对 Steam 禁用替代加载器
   - 避免进程创建拦截导致 CEF 异常

4. **D3DMetal / Apple GPTK**
   - 专有 D3D→Metal 翻译层
   - 提升游戏性能和兼容性

## 对 Whisky 的启示

- 纯上游 Wine 确实不支持 Steam CEF（引擎级限制）
- CrossOver 的修复都是 Wine 二进制层面的，无法复制
- Whisky 的 ProtonWine 模式无法通过配置参数解决此问题
- 最佳方案：使用 CrossOver 模式运行 Steam
- 或在 UI 中明确提示用户此限制
